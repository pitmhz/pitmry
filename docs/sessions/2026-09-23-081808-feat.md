## Context
This milestone follows the Phase 1 canonical-store groundwork and the project architecture rebuild docs. Phase 2 replaces the old parallel/label-fragmented memory backend with a project-local canonical store and rebuildable search projections. Migration was deliberately scoped to the two PITMRY labels; unrelated projects and legacy records were left untouched. The Phase 2 changes are present in the working tree, not in the captured Git commit.

## Rationale
Canonical records are the source of truth; SQLite/FTS and LanceDB are derived projections rebuilt from that source. Scoped migration limits cross-project contamination, stable record identity makes retries safe, full Git SHAs preserve reference integrity, and retaining duplicate summaries avoids silently discarding source history.

## Decision
Use .pitmry/memory-dashboard as the canonical project store, with SQLite/FTS and LanceDB as rebuildable projections; migrate only explicitly selected PITMRY labels and preserve source identities and duplicate history.
